Section 2 • ERD Specification

2. Entities & Relationships Detail

Detailed attribute breakdown, keys, and operational rules for all six entities.
CUSTOMER 1 : M with RESERVATION
  • PK customer_id
  • name (VARCHAR)
  • phone (VARCHAR)
  • email (VARCHAR)
A registered customer can make multiple dining reservations over time. Each reservation belongs to one customer.
RESTAURANT_TABLE 1 : M with RESERVATION
  • PK table_id
  • table_number (VARCHAR)
  • capacity (INTEGER)
  • status (VARCHAR)
A table hosts multiple reservations across different dates/times. Each reservation locks exactly one table.
RESERVATION 1 : M with ORDER
  • PK reservation_id
  • FK customer_id
  • FK table_id
  • reservation_date / start_time / end_time / status
Represents a dining slot. Multiple food orders can be placed within a single reservation session.
MENU_ITEM 1 : M with ORDER_ITEM
  • PK item_id
  • item_name (VARCHAR)
  • description (TEXT)
  • price / category / availability
Catalog of dishes. A menu item can appear across many order items in different customer orders.
ORDER 1 : M with ORDER_ITEM
  • PK order_id
  • FK reservation_id
  • order_time (TIME/TIMESTAMP)
  • status / total_amount
Contains food requests placed during a reservation session. Holds multiple distinct order items.
ORDER_ITEM M : 1 Join Entity
  • PK order_item_id
  • FK order_id
  • FK item_id
  • quantity / unit_price / subtotal
Junction line item recording quantity, agreed unit price, and subtotal per ordered dish item.

Section 5 • Data Integrity

🛡️ Referential Integrity Enforcement
  • Entity Integrity: Every table possesses a mandatory Primary Key (`customer_id`, `table_id`, `reservation_id`, etc.) that is strictly unique and non-null.
  • No Orphaned Orders: An `ORDER` cannot exist without referencing a valid, active `RESERVATION` (`order_id 501 → reservation_id 101`).
  • Cascade / Restrict Rules: Deleting a customer with active reservations is restricted to prevent invalid dining records.
  • Domain & Subtotal Consistency: Line item subtotals (`quantity * unit_price`) dynamically match order line records, ensuring financial transaction consistency.
